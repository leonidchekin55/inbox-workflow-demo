# Android-клиент для сигналов обращений

Это исходный код подготовительного приложения. Обнаружена гонка планирования при двух одновременно завершающихся заданиях: событие может остаться в очереди до следующего запуска. Для восстановления добавлена независимая периодическая проверка очереди, но её работа и устранение риска на Android не проверены. Проверка на устройстве необходима до использования. Сборка и запуск на устройстве ещё не проверены. В этом рабочем окружении отсутствуют Java и Android SDK, свободного места недостаточно для установки Android Studio. Готового APK в комплекте пока нет.

## Как предполагается подключение

1. Собрать debug APK в Android Studio с Android SDK 35, Java 17 и Gradle 8.9. Открыть каталог `android-alerts` как проект Gradle и выполнить `gradle :app:assembleDebug`. Установку и доступ к уведомлениям владелица телефона подтверждает сама.
2. На телефоне открыть приложение и скопировать его идентификатор. Зарегистрировать этот ID в `notification-hub` и безопасно передать соответствующий токен владелице. Токен не отправляют в переписке и не включают в исходники.
3. Указать HTTPS-адрес приёмника, токен и идентификаторы мессенджеров. Включить доступ к уведомлениям в системных настройках Android. Два телефона регистрируются раздельно.
4. Проверить тестовым сообщением и звонком каждый фактически используемый мессенджер на обоих телефонах, в том числе в фоне и с VPN. Выбрать группировку в приёмнике. Отдельно настроить доставку из приёмника получателю.

Приёмник в этом проекте работает локально. Телефону понадобится отдельный доступный HTTPS-адрес с доверенным сертификатом и настроенная защита. Приложение не принимает обычный HTTP и не отключает проверку сертификата. Сеть и приёмник должны быть настроены отдельно.

## Данные и ограничения

Доступ к уведомлениям предоставляет приложению возможность видеть уведомления других приложений. Этот код использует его для выбранных пакетов и не сохраняет текст. Кроме него требуется доступ к сети. Обрабатываются лишь выбранные пакеты и уведомления, которые Android классифицирует как сообщение или звонок. Приложение отправляет случайный ID события, имя пакета, случайный ID установки, тип, время и необратимый идентификатор диалога, если Android предоставляет подходящий shortcut ID. Имена, текст переписки, номера и документы не включаются в запрос. Для вычисления HMAC используется ключ Android Keystore, поэтому идентификаторы с разных телефонов и из разных приложений не совпадают. Токен зашифрован ключом Android Keystore. Резервное копирование данных приложения отключено. Очередь хранит технические метаданные в локальной базе приложения до подтверждения приёмника.

Сообщения без стабильного shortcut ID передаются без идентификатора клиента. При режиме «на клиента» это может привести к нескольким сигналам для одного человека. Обновление существующего системного уведомления также может поступить как новое событие, поэтому без ID диалога возможны повторы. Некоторые мессенджеры могут использовать нестандартные уведомления, общий ключ или другие категории, поэтому не все сообщения и звонки будут распознаны. Отключённые уведомления, блокировка фоновой работы, VPN и отсутствие сети могут задержать или скрыть событие. Счётчик первого события за день и доставки находится в приёмнике.

Повтор отправки использует то же тело и ID. Подтверждение `200` или `201` с JSON `{"accepted": true}` удаляет запись из очереди; ответ другого типа или без подтверждения сохраняет её для повтора. Остальные ответы и сетевые ошибки оставляют запись для повторной попытки. На приёмнике должны быть защита от повторов и достоверная фиксация. При ошибке конкретная запись откладывается, а другие готовые сигналы могут отправляться. Диагностика показывает последнюю ошибку или успешную отправку, и причину отказа нужно устранить. Смена HTTPS-адреса при непустой очереди запрещена, чтобы данные не ушли на другой сервер. После переустановки приложения создаются новые идентификатор и ключи, устройство потребуется зарегистрировать заново.

Поддержка iPhone не реализована. Для практического использования сначала нужна сборка, проверка безопасности и реальная проверка разрешений, уведомлений, фоновой доставки и ограничений каждого телефона.

## Вариант удалённой сборки

Файл `ci/android-debug-build.yml` — неактивный шаблон GitHub Actions. После размещения исходников и переноса файла в `.github/workflows` он запускается вручную через GitHub Actions, использует JDK 17, Gradle 8.9 и установленный на runner Android SDK 35, затем сохраняет debug APK как артефакт на три дня. Ручной запуск и размещение в репозитории здесь не выполнены. Если образ runner изменится и SDK 35 будет отсутствовать, проверка завершится ошибкой до сборки. Debug APK подписан тестовым ключом сборочной среды и предназначен для проверки, не для публикации в магазине.

Независимое периодическое задание проверяет наличие очереди не чаще раза в 15 минут и повторно ставит передачу в планировщик. Android может отложить эту проверку из-за режима энергосбережения или состояния устройства. Watchdog не доказывает точное время доставки и нуждается в проверке на каждом телефоне.
