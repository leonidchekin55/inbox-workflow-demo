# Приёмник и список уведомлений

Программа принимает минимальные сведения о событии телефона, складывает их в устойчивую очередь и показывает список на этом компьютере. Имена, текст переписки, номера телефонов и документы в запросе не используются. В событиях остаются названия приложений, ID устройства, время, тип и непрозрачный идентификатор диалога, если телефон может его определить. Эти сведения тоже нуждаются в защите.

## Подготовка

На Mac можно дважды открыть `Запустить.command`. При первом запуске программа создаст папку `~/Library/Application Support/Lena Alerts`, запустит локальный приёмник и откроет панель. Для остановки закройте окно терминала или нажмите Ctrl+C. Если папка уже существует, а какие-либо настройки или база отсутствуют, программа покажет ошибку и сохранит существующие файлы. Для добавления телефона используйте описанную ниже команду `add-device` с путём к этой папке.

Нужен Python 3.9 или новее и доступная база часовых поясов системы. Команды запускайте из корневой папки проекта, заменив путь на **новую**, ещё не существующую личную папку. Настройки можно создать до получения телефонов:

```sh
python3 notification-hub/hub.py init --data-dir ./private-alert-data --grouping client --timezone Europe/Moscow
python3 notification-hub/hub.py serve --data-dir ./private-alert-data
```

Когда телефон будет доступен, найдите ID установки в приложении телефона и добавьте его командой ниже. Замените `ID_УСТАНОВКИ` значением из приложения, без пробелов. Повторите для второго телефона. Приёмник можно оставить запущенным. Настройка не изменяет и не удаляет существующие записи.

```sh
python3 notification-hub/hub.py add-device --data-dir ./private-alert-data --device ID_УСТАНОВКИ
```

Телефоны можно добавить и при первоначальном создании папки, передав `--device ID_УСТАНОВКИ` для каждого устройства.

Откройте в браузере на компьютере адрес, который покажет программа, по умолчанию `http://127.0.0.1:8766/`. Оставьте программу запущенной, чтобы принимать события. Приёмник работает на `127.0.0.1:8765`, панель — на отдельном локальном порту. Для выбора другого порта используйте `--device-port` и `--dashboard-port` в команде `serve`.

Созданный файл `device-tokens.json` содержит ключи телефонов, а `settings.json` — режим и часовой пояс. Оба файла и SQLite-база доступны только текущему пользователю компьютера при обычных правах файловой системы. Не пересылайте ключи в чат и не включайте папку настроек в публичные архивы, Git или резервные копии с чужим доступом. Храните резервную копию защищённо: утрата базы удалит историю и учёт событий за день. Данные в базе не шифруются самой программой. Диски, резервные копии, доступ к компьютеру и время хранения нужно согласовать с владельцем данных. Программа не удаляет историю автоматически.

При подключении телефонов понадобится защищённый HTTPS-адрес с действительным сертификатом, доступный с телефонов. Служба HTTPS должна направлять **только** `/v1/events` к локальному порту приёмника и ограничивать размер запросов. Панель и файлы настроек не должны публиковаться через неё. Открывать порт приёмника напрямую в интернет или передавать ключ по обычному HTTP нельзя. Адрес и канал предоставляются при настройке; этот проект не создаёт внешний сервер или доступ в интернет.

В `Caddyfile.example` подготовлен пример маршрута для Caddy, размещённого на том же компьютере, что и приёмник. Для него потребуется отдельное доменное имя, указатель DNS на сервер, доступные порты 80 и 443 и переменная окружения `LENA_ALERTS_HOST` с этим именем. Настройка открывает в интернете путь `/v1/events` и использует ключи телефонов; сначала нужно согласовать доступ и проверить защиту, работоспособность TLS и доступность с нужной сети. Шаблон пока не запускался и не проверялся установленным Caddy. Другие пути, включая панель, получают ответ 404.

## Режимы

- `client` — один сигнал за день по устойчивому идентификатору клиента. Сопоставление диалогов между разными приложениями и телефонами автоматически не производится. Если идентификатор неизвестен, каждое уникальное событие ставится в очередь, чтобы не потерять обращение другого клиента.
- `channel` — один сигнал за день на приложение и телефон.
- `all` — один сигнал за день на все источники.

День определяется часовым поясом при создании базы. Выберите режим и часовой пояс до подключения. Первая запись определяется порядком получения, поэтому при задержке событий она может отличаться от первой по времени. Приложение телефона должно проверять видимость системных уведомлений и сохранять события для повтора. Уведомления отсутствуют, когда приложение-источник или устройство их не выдало.

## Протокол

`POST /v1/events` только по заранее настроенному HTTPS-каналу, `Authorization: Bearer <ключ телефона>`, `Content-Type: application/json`. Максимум 4096 байт. Точные поля:

```json
{"event_id":"неповторимый-id","platform":"org.example.messenger","account_id":"phone1","kind":"message","occurred_at":"2026-11-17T15:00:00+03:00","client_id":null}
```

`event_id` — стабильный ID конкретного события. `platform` — идентификатор приложения, `account_id` — заранее настроенный ID устройства. Эти значения содержат латинские буквы, цифры, `.`, `_`, `:`, `-`, до 128 символов, для `account_id` до 64. `kind` принимает `message` или `call`. `occurred_at` — ISO 8601 с часовым поясом. `client_id` — локально вычисленный HMAC диалога в виде 64 строчных шестнадцатеричных символов либо `null`. Дополнительные поля отклоняются.

Ответ 201 означает созданную запись на день, 200 — что событие принято, но отдельная запись уже существует или событие повторно доставлено. Только эти ответы подтверждают сохранение события. 409 означает повтор ID с изменёнными данными. Неуспех и потерянный ответ требуют повторять ровно тот же `event_id` и тело. Сервер различает телефоны по отдельным ключам и проверяет соответствие ID. Защищённый сетевой канал и реальный телефон здесь не настроены.

Статус «Принято почтовым сервером» означает подтверждение от SMTP-сервера, а не подтверждение прочтения или попадания во входящие. При потере ответа сервера повторная попытка может дать дубликат. Одновременно нельзя запускать несколько независимых способов доставки с общей очередью без отдельного учёта для каждого.

## Дополнительная отправка по почте

Для запуска нужны адреса отправителя и получателя и настройки SMTP, предоставленные почтовой службой. Укажите их в команде, используя свои значения. Программа запросит пароль отдельно и не сохранит его в файле. Поддерживаются STARTTLS или TLS с проверкой сертификата; пример использует STARTTLS. Сначала согласуйте отправку на выбранный адрес и проведите тест с вымышленным событием.

```sh
python3 notification-hub/email_worker.py --data-dir ./private-alert-data run --host SMTP_СЕРВЕР --port ПОРТ --sender АДРЕС_ОТПРАВИТЕЛЯ --recipient АДРЕС_ПОЛУЧАТЕЛЯ --username ИМЯ_ПОЛЬЗОВАТЕЛЯ --security starttls
```

Когда итог передачи неизвестен, программа останавливает автоматический повтор этого письма и сохраняет его на ручную проверку. После остановки отправки и проверки почты откройте список таких событий и явно выберите действие для конкретного ID:

```sh
python3 notification-hub/email_worker.py --data-dir ./private-alert-data review
python3 notification-hub/email_worker.py --data-dir ./private-alert-data resolve ID --action retry
python3 notification-hub/email_worker.py --data-dir ./private-alert-data resolve ID --action accepted
```

`retry` разрешает повторную отправку. `accepted` отмечает, что сервер принял письмо. Выбирайте одно действие после проверки результата. Не запускайте несколько независимых способов доставки с общей очередью одновременно.

Проверки:

```sh
python3 -m unittest discover -s notification-hub -p 'test_hub.py' -v
python3 -m unittest discover -s tests -v
node --check notification-hub/app.js
```
